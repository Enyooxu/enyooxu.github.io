JVM调优

发表于2026-02-10|更新于2026-10-25|JVM
|浏览量:

JVM 调优（Performance Tuning）是一项系统工程，其核心目标通常是在吞吐量（Throughput）、延迟（Latency）和内存占用（Footprint）之间寻找最佳平衡点。

  1. Minor GC 极度频繁：每秒钟发生多次，说明新生代太小或对象分配速率极高。
  2. Full GC 出现：Full GC 应该是偶尔发生的（比如几天一次）。如果每小时甚至每分钟都在 Full GC，必须调优。
  3. GC 停顿时间过长：单次停顿超过了业务可接受的阈值（如超过 500ms）。
  4. CPU 占用异常：top 显示 CPU 高，且 jstat 显示一直在做 GC 清理（频繁的 GC 会大量消耗 CPU）。

对于单台服务器来说，相对合理的范围值如下：

  1. jvm.gc.time：每分钟的GC耗时在1s以内，500ms以内尤佳
  2. jvm.gc.meantime：每次YGC耗时在100ms以内，50ms以内尤佳
  3. jvm.fullgc.count：FGC最多几小时1次，1天不到1次尤佳
  4. jvm.fullgc.time：每次FGC耗时在1s以内，500ms以内尤佳

通常来说，只要这几个指标正常，其他的一般不会有问题，如果其他地方出了问题，一般都会影响到这几个指标。

调优手段

代码层优化

再好的 JVM 参数也救不了烂代码。很多性能问题本质上是代码写法问题：

  • 减少大对象创建：例如避免在循环内不断 new 大数组或大字符串。
  • 优化本地缓存：使用 Guava Cache 或 Caffeine 时，必须设置过期时间和最大容量，防止内存溢出。
  • 合理使用单例：减少重复创建对象的开销。
  • 避免读取整表数据：SQL 查询一定要加 limit 或分页，防止一次性将百万级数据加载进堆内存。

垃圾回收器（GC）策略选择

根据业务对“延迟”和“吞吐量”的要求，选择最合适的垃圾回收方案。

  1. 追求极低延迟：使用 G1 或 ZGC。
  • G1：通过 -XX:MaxGCPauseMillis 设置预期停顿时间（默认 200ms）。它会将堆拆分成多个 Region，优先回收垃圾最多的区域。
  • ZGC：适用于超大内存（8GB~16TB），能将停顿时间控制在 10ms 以内。
  1. 追求高吞吐量：使用 Parallel GC。
    适合后台数据处理、科学计算等对停顿不敏感的业务。

内存区域配置优化

这是最直接的手段，通过调整 JVM 各个堆区域的大小，减少 GC 频率和停顿时间。

  1. 堆大小对齐（-Xms = -Xmx）
    如果初始堆内存和最大堆内存设置为不同的值，会发生动态扩容和缩容。当 -Xms 小于 -Xmx 时，JVM 的工作逻辑如下：
  • 扩容：当现有的堆空间不足以分配新对象，或者 GC 后剩余空间低于某个百分比（如 MinHeapFreeRatio）时，JVM 会向操作系统申请更多内存。
  • 缩容：当 GC 后发现空闲内存太多（高于 MaxHeapFreeRatio），JVM 会为了节省系统资源，将内存还给操作系统。

如果-Xms 和 -Xmx不相等，JVM 会根据负载动态调整堆空间，这个过程就像一个会变大变小的“气球”，而“震荡”指的就是气球频繁扩缩容带来的系统损耗。发生损耗的点如下：

  • 申请内存开销：向内核（Kernel）申请物理内存页是一个相对重的操作，涉及系统调用。
  • 触发额外的 Full GC：在很多情况下，JVM 为了决定是否要扩容或缩容，会先触发一次 Full GC 来清点资产（查看存活对象）。频繁的扩缩容意味着频繁的 Full GC。
  • 计算损耗：JVM 需要不断计算当前的空闲比例，判断是否达到了触发扩缩容的阈值。

  1. 新生代比例调整（-XX:NewRatio）
    通常设为 2（老年代:新生代 = 2:1）。如果你的应用产生大量短生命周期的对象，应适当调大新生代，让对象在 Minor GC 阶段就被清理，避免进入老年代。

  2. 元空间固定化（-XX:MetaspaceSize）
    如果元空间扩容会触发 Full GC。建议将 MetaspaceSize 和 MaxMetaspaceSize 设置为相同的值，防止启动初期频繁 GC。设置相同的理由其实和堆大小对齐类似。

关键参数微调

通过细节参数优化对象的“晋升”机制：

  1. 晋升年龄限制（-XX:MaxTenuringThreshold）
    对象在 Survivor 区经过多少次 Minor GC 后进入老年代。默认通常是 15。如果老年代空间压力大，可以适当调大此值。
  2. 大对象直接入老年代（-XX:PretenureSizeThreshold）
    设置一个阈值，超过该大小的对象直接分配到老年代，避免在新生代的两个 Survivor 区之间来回复制，浪费 CPU。

调优步骤

  1. 分析和定位当前系统的瓶颈
  1. 确定优化目标
    定位出系统瓶颈后，在优化前先制定好优化的目标是什么，例如：
  • 将FGC次数从每小时1次，降低到1天1次
  • 将每分钟的GC耗时从3s降低到500ms
  • 将每次FGC耗时从5s降低到1s以内
    …
  1. 制订优化方案
    针对定位出的系统瓶颈制定相应的优化方案，常见的有：
  • 代码bug：升级修复bug。典型的有：死循环、使用无界队列。
  • 不合理的JVM参数配置：优化 JVM 参数配置。典型的有：年轻代内存配置过小、堆内存配置过小、元空间配置过小。
  1. 对比优化前后的指标，统计优化效果
  2. 持续观察和跟踪优化效果
  3. 如果还需要的话，重复以上步骤
