现在有一个需求是在查询数据库中的数据时，希望数据返回时lang字段为一个Map<String, MultiLanguageDTO>类型，如果不做任何配置，mybatis是无法做到的。

解决方法

对于TableField中属性做一个解释，

typeHandler

可以把他理解为Java 类型 和 JDBC 类型 之间的转换器。在默认情况下MyBatis/MyBatis-Plus是不知道如何把 LONGTEXT 转成 Map，也不知道如何把 Map -> LONGTEXT，有了这转换器以后，无论是在查询还是保存的时候，MyBatis/MyBatis-Plus就知道如何将这两种类型转换，这里的MySqlMapHandler.class需要我们自己去定义。

注意这里需要重写四个方法，这里一次说明一下：

  1. setNonNullParameter
    这个方法是往数据库写数据时调用的，比如说新增和更新。
  • PreparedStatement ps:JDBC 的预编译对象。相当于insert into xxx(lang) values(?)中的?。我们要做的就是给这个 ? 赋值。
  • int i：第几个参数。例如：insert into user(name, lang) values(?, ?)那么name 是 1, lang 是 2。
  • parameter：真正的 Java 对象。也就是private Map<String, MultiLanguageDTO> lang;。
  • jdbcType:数据库字段类型。这里一般是JdbcType.LONGVARCHAR。

这个方法里面的写法基本上是固定的。

  1. getNullableResult(ResultSet rs, String columnName)
    其实下面这个三个方法都是读取数据库的时候调用的，通俗点讲就是怎样讲数据库中的longtext类型数据转成Java中的Map<String, MultiLanguageDTO>，这三个方法只是调用场景不同，实现的时候的逻辑是完全一样的。当前这个方法是通过列名读取时调用。例如：select lang from user,MyBatis 内部调用rs.getString("lang")。

  2. getNullableResult(ResultSet rs, int columnIndex)
    这是通过列下标读取时调用。例如：select lang,name from user，JDBC 内部：rs.getString(1)。这里：1 => lang，2 => name。
    有这种方式取值的原因是MyBatis 有时按列名取，有时按下标取。具体会取决于：SQL解析方式、自动映射、性能优化、ResultMap配置等。

  3. getNullableResult(CallableStatement cs, int columnIndex)
    这是调用存储过程时使用。例如：CALL test_procedure(?), 对应 JDBC：CallableStatement。一般项目几乎用不到 因为现在很少大量使用。

jdbcType

这个属性是告诉 MyBatis 数据库中的 JDBC 类型是什么。有时候不写 jdbcType 也能运行。因为 MyBatis 很多时候能自动推断。例如：String name。数据库：VARCHAR,MyBatis 自动就知道怎么映射。但是对于复杂的Java对象映射，比如说本例中，他就无法自动识别了，所以这里一定要加上该属性。
