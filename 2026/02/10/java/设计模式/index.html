Java中的设计模式

发表于2026-02-10|更新于2026-10-25|Java
|浏览量:

Java 中的设计模式本质上是在软件设计过程中反复出现的问题的成熟解决方案。它不是现成代码，而是一种设计思想和结构模板。经典的设计模式共有 23 种，按照用途分为三大类：

  • 创建型模式（Creational） —— 解决“对象怎么创建”
  • 结构型模式（Structural） —— 解决“类和对象怎么组织”
  • 行为型模式（Behavioral） —— 解决“对象之间怎么协作”

创建型模式

工厂模式

工厂模式在开发中是最为常见的设计模式之一。其核心思想是把对象创建交给工厂，而不是业务代码自己 new。工厂模式在 Java 中通常分为三种：简单工厂、工厂方法、抽象工厂，下面来一一介绍。

单例模式

单例模式的核心是保证一个类在 JVM 中只有一个实例，并提供全局访问点。一般在配置中心、日志对象、线程池 、缓存管理器使用较多。

饿汉式

优点：他是线程安全的。因为类加载天然线程安全。
缺点：可能会浪费资源，因为这个实例在JVM启动的时候就会初始化，即使用不到也会初始化，所以可能会造成资源的浪费。

所以这种饿汉式适用于对象小且一定会用到的时候使用最佳。

懒汉式

懒汉式的核心是用到的时候再去创建。

这个模式有一个致命缺陷，它存在线程安全问题，因为如果同时有两个线程都调用了getInstance且他们都发现instance为null，那么就会创建两个单例，此时就违背了单例原则了。

synchronized 懒汉式

这种是对上面懒汉式的一种加锁补充，虽然解决了线程安全问题，但是他的性能很差，即使是这个单例已经被创建出来了，但在每次调用的时候都会去加锁、解锁，在高并发情况下影响很明显。

  3. 可以防止反序列化破坏，普通单例反序列化后可能新建对象并返回一个新的实例。而JVM保证反序列化仍是同一个实例。

致命缺陷：

  • 不能代理 final 类：因为 CGLIB 靠继承实现，而 final 类是无法被继承的。
  • 不能拦截 final 或 private 方法：子类无法重写父类的 final 或 private 方法，因此这些方法无法被动态织入增强逻辑，调用时会直接走原方法体。

总结：

  1. JDk 动态代理和CG Lib动态代理的区别
对比项 JDK 动态代理 CGLIB 动态代理
实现机制 基于 Java 反射机制，通过接口生成代理类 通过继承目标类生成子类代理
目标要求 目标类必须实现至少一个接口 目标类无需实现接口（可以代理普通类）
性能 开销较大，性能较低（JDK8+ 已优化） 直接调用方法，性能接近原生调用
生成方式 运行时通过 Proxy.newProxyInstance() 运行时通过 Enhancer.create()
局限性 无法代理未实现接口的类 无法代理 final 类或 final 方法
依赖 JDK 原生支持 需要引入 CGLIB 库

优点：

  • 解耦：Subject只负责通知，其他的并不关心
  • 支持广播：天然支持一对多。
  • 动态订阅：运行时添加或删除，非常很灵活。
  • 符合开闭原则：新增观察者无需改 Subject。

缺点：

  • 通知链难追踪：当观察者数量多了以后，出现问题配查问题非常困难；
  • 性能问题：观察者很多了会导致通知开销大。同步通知尤其明显。
  • 循环依赖：例如A通知B，B又通知A，可能出现死循环。
  • 顺序不可控：多个观察者的执行顺序是不固定的。

责任链模式一般有两种模式分别是纯责任链和非纯责任链。

  • 纯责任链模式：就是上述举的这个例子，他的特点是只能有一个节点处理。spring中的HandlerInterceptor是一个经典实现，当返回false的时候，链就停止了。
  • 非纯责任链模式：多个节点都可以处理，每个链都会执行一遍。最经典的实现是Filter，在过滤器链中每一处都需要执行。

优点：

  • 解耦：发送者不知道谁处理只发请求。
  • 动态组合：链可配置。例如：运行时可以是A→B→C也可以是A→C，配置起来非常灵活。
  • 符合开闭原则：新增处理者。无需改旧代码。
  • 单一职责：每个节点只干一件事。

缺点：

  • 调试困难：链长难排查。不知道卡在哪。
  • 可能无人处理：如果next == null,请求就会丢失。所以通常需要有默认节点。
  • 性能问题：链很长时开销将越来越大。
  • 循环链风险：假如设置了A→B→C→A，那么就会有死循环的风险。
