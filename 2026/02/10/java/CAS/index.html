简介

CAS 全称是 Compare And Swap（比较并交换），CAS 是一种无锁的同步机制。它包含三个操作数：CAS(V, E, N)

  • V：内存中的实际值（Value）
  • E：期望值（Expected）
  • N：新值（New）

为何需要使用CAS

举个例子：
当前，count = 0 ，两个线程同时进行 count++ ，而 count++ 不是原子操作，而是由以下几个步骤构成：

  • 读取count
  • +1
  • 写回count
  1. 线程A读到 count = 0，此时线程B读到 count = 0；
  2. 线程A执行count++，同时线程B也执行count++；
  3. 线程A将结果写到count，同时线程B将结果写道count；

最终造成的结果就是count的值还是为1，但是我们想要的结果是2，这就是线程安全问题。传统解决办法通过加synchronized方法，但是其缺点也很明显，如：线程阻塞、线程切换、性能下降。于是，便出现CAS。

工作原理

还是以上面的count的累加来举例，前面的步骤完全相同：

  1. 线程A读到 count = 0，此时线程B读到 count = 0；
  2. 线程A执行count++，同时线程B也执行count++；
  3. 当A执行完成以后将count的值变为1时，他会判断当前值为多少，如果为0，那么就将count的值赋值为1。
  4. 此时当线程B来赋值的时候发现count的值已经是1了，此时B的值不会用新的值去覆盖旧的值。
  5. 通常情况下会重新读取count的值，随后再次重复执行上述操作。

上述所说的重复执行的这一步骤就是CAS的自旋。简单来说就是CAS操作失败以后不会睡眠，而是继续尝试。CPU一直在运行状态。

CAS的模板实现

实际上在Java中的Java.util.concurrent.atomic包下有很多模板方法都是通过CAS来实现的，如：

  • AtomicBoolean
  • AtomicInteger
  • AtomicLong
  • AtomicReference
  • AtomicIntegerArray
  • AtomicLongArray
  • AtomicReferenceArray
  • AtomicStampedReference (解决ABA问题)
  • AtomicMarkableReference

实际上在开发过程中使用这些类的地方不算是很多，当对某一个参数有计数要求时，且会发生并发写的时候，就可以使用了。

CAS 的应用

  • 实现无锁队列、栈等数据结构
  • 乐观锁实现的基础
  • AQS、Lock 等并发工具的实现基础
  • volatile 变量的原子更新
  • concurrentHashmap 中在1.8之后的枷锁策略为CAS+Synchronized

优点

  1. 高性能：避免线程阻塞和上下文切换
    使用synchronized失败以后，当前线程会被阻塞，等待后续被唤醒，线程切换代价从：用户态 -> 内核态 -> 用户态，开销非常大。而CAS不同，CAS在失败以后会重新尝试，不会将当前线程挂起，也就是没有上下文的切换，所以在低竞争下，CAS会非常快。
  2. 无死锁：没有锁的获取和释放
  3. 可扩展性：在高争用环境下表现更好

缺点

  1. ABA问题

  1. 长时间自旋
    例如现在有100个线程一直CAS失败，那么CAS会一直自旋CPU会一直在告诉运转，这会对CPU产生很大负担。所以CAS适合竞争不激烈的场景，当竞争特别高synchronized效果反而可能更好。

Tip

  1. CAS是如何保证原子性的，从上述来看明明是两个步骤，比较并交换明明是两步。
    CPU 提供了例如x86：CMPXCHG这一条 CPU 指令。CPU 会保证比较、交换整个过程不可中断。CAS 是硬件级别支持的，不是 Java 自己保证的。
